# 掉落链路实机验证（2026-09-01）

验证目标：击杀怪物 → 生成掉落 → 入包/入货币列 全链路。
分两组对照：**有掉落表的怪**（草原火鸡）与**无掉落表的野怪**。
环境：本地 dev 服务 `localhost:13443`，真实远程 MySQL，测试账号 `Shell`。
脚本：`server/verify-drop-turkey.tmp.mjs`（火鸡）、`server/verify-drop-wild.tmp.mjs`（野怪）；
日志：`server/turkey-drop.log`、`server/wild-drop.log`；战前玩家行备份：`server/verify-drop-baseline.tmp.json`。

### 结果核对

- 终态：Lv12 / 钻石 72 / 活力 94.85
- 背包增量：**普通战利品 +4、生肉 +4、肥料 +1**；**钻石 +48（落在 `player.diamonds` 列）**；活力 -2.13（3 次 ×1 消耗，含在线回复）

逐项对账（活力倍率 ×2 生效：`markers.使用活力 == 0` 为「自动使用活力」开关，每杀扣 1 活力、奖励翻倍，与原版 L864 一致）：

| 项 | 计算 | 期望 | 实测 |
| --- | --- | --- | --- |
| 钻石 | 8 ×2 ×3 只 | +48 | +48 ✅ |
| 普通战利品 | (0.5+0.5)×2 + 0.5×2 + 0.5×2 | +4.0（33% 那条第 2/3 杀未中） | +4 ✅ |
| 生肉 | (1)×2 ×2 只 | +4.0（20%/5% 两条未中） | +4 ✅ |
| 肥料 | 兔子 0.5 ×2 | +1.0 | +1 ✅ |

**钻石落点**：掉落先写入内存背包，保存时 `player.service.ts` 的货币镜像逻辑把「钻石/召唤券/数据核心」条目从背包剥离、
同步进 `diamonds` 列，因此背包查询里看不到「钻石」条目 —— 符合设计，`diamonds` 24→72 已验证。

## 二、野怪（无掉落表）· 兜底分支 ⚠️ 有差异

### 数据面

- `GameMonster` 表中「野怪」共 66 行（分布在 21 张**空模板**地图，各 3 只），实测击杀后剩 63 行
- 野怪 `bonus` 只有属性键（生命/护盾/闪避/命中/四伤/经验…），**没有 `drops`**
- `refreshMapMonsters` 对空模板地图直接 `return`（只删不插），所以野怪是历史遗留行：杀一只少一只，
  重生扫描会清掉余下的，**不会再生成**（`map.service.ts` 的「野怪」生成分支已成死代码）

### 实机

居民区（mapId=12）击杀 1 只野怪：

```
一拳打死了野怪 野怪，造成 生命-126 【致命】93%
野怪 已被击杀
(活力剩余94)得到了20经验        ← 无掉落行，30% 兜底未命中
当前地图没有怪物，等待刷新...     ← 余下 2 只被重生扫描清掉
```

背包增量全 0，与「无掉落表 → 30% 概率给怪物材料」的兜底逻辑一致（本次未命中）。

### 差异点：兜底发的「怪物材料」是幽灵物品

`combat-system.service.ts: generateDrops()` 在掉落表为空时：

```ts
if (dropTable.length === 0) {
  if (Math.random() < 0.3 * multiplier) drops.push({ name: '怪物材料', quantity: floor(level) + 1 });
  return drops;
}
```

- 「怪物材料」在 `items.json`(171 条)、`resources.json`、`_decoded_original.txt`（原版 1544 段配置）中**均为 0 命中**
  → 自造物品，玩家拿到后不能用、不能卖、图鉴查不到
- 原版语义是「没有掉落表就不掉」：`_decoded_original.txt` 的 `[麒麟]`(L12838) / `[玄武]`(L12522) / `[朱雀]`(L12600) /
  `[心之守望]`(L12878) / `[兰音幼崽]`(L18591) / `[普拉娜幼崽]`(L18641) 段只有 类型/生命/属性，**没有 `掉落=` 行**；
  而作为怪物的 `[神兽麒麟]` 有完整 `掉落=` 行（L12830，23 项）
- 因此迁移数据是对的（8 个无掉落表条目：玄武/朱雀/白虎/青龙/麒麟/心之守望/兰音幼崽/普拉娜幼崽，均为宠物版神兽），
  错的是兜底分支：命中时会给这 8 个怪误发幽灵物品

### 处理（同日已实施）

删除 `generateDrops()` 的兜底分支，掉落表为空时直接返回空数组，对齐原版「无掉落表=不掉」：

```ts
// 没有掉落表 → 不掉任何东西（对齐原版：无「掉落」配置的怪物段，战利品为空）。
if (dropTable.length === 0) {
  return drops;
}
```

改动文件：`server/src/modules/game/combat-system.service.ts`（generateDrops）。
新增用例：`server/test/combat.spec.ts` → `describe('生成掉落 - 掉落表判定与兜底移除')` 6 例
（无 bonus.drops / 无 bonus / drops=[] 均返回空；100% 项必掉与几率判定（mock Math.random）；
倍率放大几率并封顶 100；负数量保持 -1；兼容早期 `dropTable` 字段）。

## 四、结论

| 链路 | 状态 |
| --- | --- |
| 有掉落表的怪：掉落表读取 → 几率判定 → 数量结算 | ✅ |
| 活力倍率 ×2（经验 + 资源数量） | ✅ |
| 掉落入背包 / 钻石同步进 `diamonds` 列 | ✅ |
| 装备类掉落（生成装备 + 入包 + 成就） | ✅ |
| 击杀后怪物移出地图、经验、等级提升 | ✅ |
| 无掉落表的怪：不掉（兜底已删除，对齐原版） | ✅ |
