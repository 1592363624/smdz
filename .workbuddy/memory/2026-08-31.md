## 图鉴（Handbook）20 分类完整复刻

玩家实测发现「图鉴」命令详情与原版差距过大——只输出 description 段落，缺少 数据显示.ecode
L2970-3530 中的伤害属性四元、技能等级替换、词条池展开、好感 20/40/60/80/100 五段解锁链、
特效编号(调试用)、毛发、通道、自带怪物/资源等调试字段；原版 20 个分类，新版只有 12 个。

### 重构方案
- 抽出独立服务 `server/src/modules/game/handbook.service.ts`，把 20 分类数据源 + 详情渲染
  + 跨分类搜索全部迁过去；`game.service.handleHandbook` 退化为薄壳入口（取得玩家 +
  标记 → 委托）。
- 数据 → 分类映射：使魔(familiars 31)/武器(equipments.isWeapon 122)/装备(other 238)/
  物品(items 170)/资源(resources 119)/地图(maps 90)/怪物(monsters 145)/任务(tasks 87)/
  增益(buffs 19)/建筑(buildings 105)/称号(titles 140)/载具部件(vehicles 扣模板 165)/
  攻击文本(attack-texts 67)/对话文本(npcs 20)/装备特效(effects.limit=装备)/
  武器特效(effects.limit=武器)/配方(craftings noCraft=false)/废弃载具(vehicle-parts 184)/
  图片(占位 0)/音乐(占位 0)。
- 详情渲染完全按原版 L2970-3530 段落顺序：
  - 武器：`◆伤害属性:物%/冰%/火%/电%` + `◆攻击显示的文本` + `◆攻击冷却` +
    `◆攻击需要锁定 N 秒` + `◆割裂/灼烧/深寒/感电` 四种负面 + 共用段
    `◆命中时触发效果` + `◆加成` + `词条池展开`（随机护盾/装甲/生命/攻击/防御/特殊
     → 具体属性列表，复刻 L3023-3028 的 6 个特殊标记替换）+ 出处 + 特效编号
  - 防具：`◆攻击时召唤【文本】` 替代
  - 资源：`名称,可采集次数 N,消耗时间 X~Y` + 采集产出（基础倍率 + 玩家倍率两行）
    + 产出 2（每日生成、发电优先级）+ 出处
  - 地图：`复活点 + 不刷特殊/家园/副本/不可传送 + NPC 数量 + 自带的资源/怪物 + 通道（按距离排序）`
  - 怪物：基础图鉴（保留「1、显示详细数据」入口，详细版留待下批）
  - 使魔：`取图片(输入)` 改为略；`名称(好感N)` + 说明2/说明/技能说明（替换【X技能等级】）
    + `好感 20/40/60/80/100 解锁:` 五段链 + `特效编号(调试用)` + `毛发:name x count`
- 入口路由：
  - `图鉴` → 20 分类总览
  - `图鉴<分类>` → 该分类列表
  - `图鉴<地点>附近` → 该复活点附近地图（编号直达）
  - `图鉴<关键词>` → 跨分类模糊搜索：1 命中→详情、1-30 命中→列表、>30 → 截断
  - `图鉴载具` → 5 类部件二级入口（核心/功能/武器/防御/行走）
  - `图鉴攻击文本` / `图鉴对话文本` → 列表（原版这两类不支持模糊搜索）
- 好感链渲染：好感 < N×20 显示 `好感{N}解锁:...`；>= N×20 直接显示原文。
- 技能等级替换：`substituteSkillLevel(text, level)` 从大到小匹配 18 个占位符（`10/5/4/3/2.5/2/
  1/0.75/0.5/0.25/0.2/0.1/0.05/0.04/0.03/0.025/0.02/0.01/0.005 技能等级`），当前玩家的
  skillLevel 由现有 `PlayerService.getSkillLevel(markers, familiarName)`（L201-208，等价
  原版 L1770-1846 熟练度→等级换算）提供。

## 图鉴第二轮：总览格式 / 精确匹配 / 怪物详细 / 数据补齐

上一批（20 分类 + 详情字段）交付后玩家实测仍指出三处与原版不一致，且发现一处数据映射错误。
本批全部修复。

### 1. 总览改为原版两列编号菜单（L2654）
原来是竖排 `【使魔】31条`，原版是：
```
路人乙请选择分类
 1、使魔       2、武器
 ...（20 项两列，编号右对齐 2 位）
或者你可以"图鉴腰部"来搜索
当前:使魔31,武器和装备360,...,配方94,废弃载具11
```
- 新增 `displayWidth`（CJK 算 2）/ `padToWidth` 做两列对齐；`CATEGORY_MENU` 定义 20 项顺序。
- 统计串 20 项口径**与菜单不同**：武器/装备合并、「部件」在统计串叫「载具部件」、多一个「制造」（菜单无入口）。
- 菜单第 11 项原文是「部件」不是「载具部件」。

### 2. 模板行过滤（关键口径修正）
原版每个数据数组首条是占位配置，运行时不计入条数。统一过滤**名称以「模板」结尾**的行后，
逐项对上原版基线：items 170→**169**、tasks 87→**86**、buffs 19→**18**、
buildings 105→**104**、npcs 20→**19**、vehicles 166→**165**。
「制造」是例外——原版统计**包含**占位行（426），`rawList('craft')` 不过滤。

### 3. 精确名称优先（L2672-2965）
新增 `findExactByName`，按原版固定**扫描顺序**（装备→使魔→资源→地图→怪物→任务→物品→
增益→建筑→部件→称号→音乐→装备特效→武器特效→图片→配方→废弃载具→攻击文本→对话文本）
找同名条目，命中直达详情。
**扫描顺序 ≠ 菜单顺序**（装备排第 1、使魔第 2）——这是 `图鉴花园猫` 从 9 条模糊结果
变回直达详情的关键。

### 4. 怪物「详细数据」分支（L3170-3245）
`图鉴X详细` 走 `renderMonsterDetail`，从 monsters.json 的 `bonus` 读（武器/装备/载具/
drops/麻醉 都已迁移），输出：属性面板 → 三池四系抗性 → 暴击伤害/韧性 → 二阶回复 →
击杀经验/必中 → 使用的武器/装备/载具 → 闪避冷却 → 掉落(基础 + 你的加成) → 麻醉值 →
被动效果 → 出处 → 说明。
- **坑**：二阶回复在静态数据里是"每秒百分比"（如 0.01），用 `roundText` 取整会被抹成 0，
  必须改用 `fmt2` 保留 2 位小数。
- 玩家侧加成（掉落率/掉落品质/宝石缎带/世界等级）由 game.service 算好经 ctx 传入，
  取不到回退 0。

### 5. 数据补齐 + 映射纠错
- **纠错**：`craftings.json`(426) 是原版**「制造」**，不是「配方」。原版「配方列表」是另一个
  94 条数组。上一批映射表作废。
- 新增 `server/scripts/extract-recipes-wrecks.js`，按 数据存取.ecode 规则从 使魔大战.txt 抽取：
  - 配方 94 条 → `prisma/data/recipes.json`（段名去"配方"、产出/消耗分 3 段、解锁需求去数字/取数字）
  - 废弃载具 11 条 → `prisma/data/wrecks.json`（原版几率编码在名称里，新版拆成 chance 字段）
- 两者注册进 `StaticDataService.DATA_FILES`。

### 6. 结构重构
`handbook.service.ts` 收敛为 `rawList` / `entryName` / `buildEntry` 三个统一入口，
删掉 20 个旧 `sectionXxx()`。分类键、菜单顺序、扫描顺序拆成独立常量
（`CategoryKey` / `CATEGORY_MENU` / `EXACT_SCAN_ORDER`）。

### 8. 剩余差异（数据层面，已在进度清单 9.8 列表）
武器和装备 360 vs 348、地图 90 vs 89、武器特效 35 vs 48、装备特效 7 vs 20、

### 教训
- **"分类顺序"要区分"展示顺序"和"匹配顺序"**：原版两者不同（菜单里使魔第 1，扫描时装备第 1）。
  之前合在一起导致精确匹配行为不对。以后遇到多分类遍历，先确认用的是哪个顺序。
- **静态数据里的"每秒百分比"类字段不能用整数取整**：0.01 会被抹成 0，看起来像"没生效"。
  凡是数值 < 1 的百分比要保留小数。
- **数据数组首条常是配置占位**：做计数/遍历前先确认是否存在模板行，否则条数对不上基线。
  但要注意例外（原版"制造"的统计含占位行）。
- **JSON 文件名有歧义时别靠猜归属**：craftings 看着像"配方"实为"制造"，
  应以原版源码里数组名（`制造列表` vs `配方列表`）和条数基线双向验证。

## 高光时刻动画（任务达成 / 领取任务 / 获得称号 / 升级）

### 需求
公屏里「完成了任务:X，得到了:Y」「并领取了新的任务:Z」「恭喜你获得了称号「T」」
「⭐ 等级提升了！Lv.a → Lv.b」只是普通文字流，希望有屏幕级炫酷动画提示。

### 实现（前后端双通道，互为兜底）
后端新增 `server/src/modules/game/highlight.service.ts`：
- `GameHighlightService` 持有 Socket.IO server 引用，由 `ChatGateway.afterInit` 注入
  （沿用 `ChatService.setServer` 同款模式，**刻意不走构造函数 DI**，避免与
  CommandModule/GameModule 形成循环依赖）。
- 事件名 `game:highlight`，按 `user:{userId}` 房间定向推送，不写库、异常静默兜底。
- 埋点：
  - `task.service.ts` → `emitTaskHighlight()`，在 advance / completePendingTask /
    acceptTask 三处结算后调用，与 `formatCompletionMessage` 共用同一份 completed 数据
    （保证公屏文本与弹窗内容一致）；奖励里过滤掉「对你的好感+X」。
  - `achievement.service.ts` → `checkTitles` 发放称号时推 `title`。
  - `familiar-system.service.ts` → 领取使魔称号，**落库成功后**才推（避免"弹了动画没拿到"）。
  - `player.service.ts` → `applyLevelUps` 是升级唯一漏斗，升级即推 `level-up`。
- 全部用 `@Optional()` 注入，存量测试桩手工 new 时不传也不受影响。

前端：
- `web/src/components/GameHighlight.vue`：冲击波 + 流光 + 能量条 + 旋转光环 +
  8 枚迸发粒子 + 弹性入场 + 奖励错峰淡入；4 类各自配色；同屏上限 3 条、停留 3.6s。
- `web/src/utils/gameHighlight.js`：`parseHighlights()` 解析公屏文本兜底，
  覆盖未埋点历史路径与 AstrBot 渠道。
- `ChatView.vue`：监听 `game:highlight` + `appendMessage` 里调 `highlightFromMessage`。

### 两个必须记住的坑
1. **归属判断**：别人完成任务时公屏也广播同款文本，兜底解析必须用
   `isOwnSystemMessage(msg)` 拦掉，否则会给别人放动画。
2. **3 秒去重窗口**：结构化事件与文本解析会命中同一次结算，不去重就连弹两遍。
   `pushHighlight()` 内以 `type|names|detail` 为签名做去重。
