# 2026-09-01 工作日志

## 掉落链路补充验证（击杀 → 掉落 → 入包）

用户提出：野怪无掉落表，改用有掉落表的怪（草原火鸡）跑一次击杀掉落入包验证。

### 方法与可复用脚手架
- 脚本：`server/verify-drop-turkey.tmp.mjs`（火鸡）、`server/verify-drop-wild.tmp.mjs`（野怪）；
  日志 `turkey-drop.log` / `wild-drop.log`，战前行备份 `verify-drop-baseline.tmp.json`。
- 套路：`/auth/dev/login` 取 token → `POST /api/commands/execute {command}` 执行指令 →
  `gm 修改玩家 <名> mapId N` 传送、`gm 修改玩家 <名> maxHp/hp 99999` 临时拉血（结束还原）→
  每 5.5s 一次 `攻击`（武器冷却）→ 用 Prisma 直读 DB 比对增量。
- 想指定怪种：不能用刷新（随机模板），直接 Prisma 克隆一条目标怪行（去掉 id/createdAt/updatedAt，
  换 qq）插 3 只 → `residentCount == monsterCount` 不会被重生扫描顶掉。
  注意杀到 residentCount < 3 会触发整批重生、随机刷进别的怪（本次第 3 杀被兔子插队）。

### 结论（详细报告：server/docs/drop-chain-verification-2026-09-01.md）
- 有掉落表的怪 ✅ 全链路通过：火鸡 2 杀 + 兔子 1 杀，钻石 +48、生肉 +4、普通战利品 +4、肥料 +1，
  逐项与 monsters.json 掉落表对账一致（全部含活力倍率 ×2）。
- 钻石落点：掉落写内存背包 → 保存时 player.service 货币镜像把「钻石」条目剥离并同步 `diamonds` 列，
  背包里查不到钻石条目是设计如此，不是丢掉落。
- 活力倍率：`markers.使用活力 == 0` 是「自动使用活力」开关（不是一次性标记），
  每杀扣 1 活力、经验与资源数量 ×2，每杀都生效 —— 与原版 L864 一致，非 bug。
- 野怪（type=野怪）bonus 无 drops：是空模板地图的历史遗留行（66 行 / 21 张图），
  `refreshMapMonsters` 对空模板地图只删不插 → 杀一只少一只、不再生成，野怪生成分支已成死代码。
- ⚠️ 差异：`generateDrops()` 掉落表为空时 30% 给「怪物材料」×（等级+1），但「怪物材料」在
  items.json(171)/resources.json/_decoded_original.txt 里 0 命中 → 幽灵物品。原版无掉落表就是不掉
  （原版 [麒麟]/[玄武]/[朱雀]/[心之守望]/[兰音幼崽]/[普拉娜幼崽] 段确无 `掉落=` 行）。
  会在 8 个无掉落表的原版怪身上误发。建议删除兜底分支（待用户确认，未改代码）。
