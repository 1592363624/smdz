## 修复：网页端背包富卡片三个 bug（web/src/components/RichSystemCard.vue）

用户反馈（附截图）：背包下方出现文字版 / 悬浮时屏幕疯狂抖动 / 看不到图鉴信息。

### Bug A：背包下方多渲染一份文字版
- **根因**：Vue `v-if` 互斥链错配。图鉴弹层 `rc-handbook`（`v-if="active.visible"`）被插在 `rc-bag`（`v-if`）与 `rc-profile`（`v-else-if`）之间，导致末端的 `rc-raw`（`v-else`）实际是与**弹层的 v-if** 配对，而非 `rc-bag` → 绕过 `layout.kind === 'bag'` 判定，背包卡片后仍渲染原始纯文本兜底。
- **修复**：用 `<template v-if="layout">` 包裹主内容三分支（bag / profile / v-else raw），弹层移到该 template **之后**作为独立 `v-if`。
- **教训（通用）**：Vue 中 `v-else` 只与**最近的前置 v-if/v-else-if** 配对；在互斥链中间插入独立 `v-if` 元素会静默打断链路，且不会报错，极难排查。任何浮层/弹层务必放在主内容互斥链之外。

### Bug B：悬浮时屏幕疯狂抖动
- **根因**：`onCellEnter` 每次 `mouseenter` 都无条件重算弹层 `left/top` 并反复重设 `active.visible = true`；"同物品已展示则 return"的判断写在 `setTimeout` 回调里，为时已晚。
- **修复**：
  - 提前 return：同物品且已有 content/error/loading → 不重算位置、不重发请求、不 toggle。
  - 缓存命中走同步分支直接 `visible = true`，不再进定时器。
  - `visible = true` 只在真正要显示时设置一次。

### Bug C：看不到图鉴信息
- **根因**：响应层级取错。`web/src/api/index.js` 的 axios 响应拦截器已 `return res.data`（剥掉外层 `{success, data}`），组件拿到的 `res` 本身就是 `CommandResult = { success, content, broadcast, durationMs }`；原代码只取 `res?.data?.content` → `undefined` → 内容为空。
- **修复**：改为 `String(res?.data?.content ?? '') || String(res?.content ?? '')` 双兼容；`visible` 在请求**前**设置（加载态即可见）；仅成功内容入 `handbookCache`，空/错误结果不缓存。

### 其他
- 曾误给 `ChatView.vue` 的 `visibleMessages` 加"相邻同内容去重"逻辑，判断为误改显示逻辑（会误伤用户重复发同一指令的正常场景）已**完整回滚**；已用 `git diff --ignore-cr-at-eol` 验证该文件零实质改动（仅行尾符差异）。

### 关键链路备忘

### Bug A：装备类点击发错指令（应区分"穿上"vs"使用"）
- **根因**：RichSystemCard.onEquip 无条件发"穿上"，未区分装备/消耗品。
- **修复**：parseLayout 给每个 item 打 `kind: 'equip' | 'use'`，启发式规则：剥掉尾部·特效后名字以大写品质码（[EDCBASX]）结尾 → 装备，其他 → 消耗品。点击时根据 kind emit `穿上 X` 或 `使用 X`。格子 title 提示也跟着改（"点击穿上「…」" / "点击使用「…」"）。

### Bug B：穿上装备报"背包中没有"（后端匹配 bug）
- **根因**：`game.service.ts:handleEquip`（第 2357 行）用严格匹配 `item.name === normalizedName`，但背包里 item.name 只存基础名（"防弹上衣"），用户输入的"防弹上衣D"（带品质码）匹配不上。

  2. 剥除尾部单字母品质码（[edcbasx] 大小写）+ 可选·特效，再用基础名匹配；
  3. `formatEquipmentInventoryDisplay(item) === normalizedName` 全名匹配。
- **关键设计**：用户在富卡片看到的 name（"防弹上衣D"）就是 formatEquipmentInventoryDisplay 的产物，因此第三层匹配能命中所有用户从背包富卡片点过去的情况。

### Bug C：图鉴弹层太重（用户要求"用 tips 那种样式"）
