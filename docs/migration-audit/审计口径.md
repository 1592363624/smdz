# 审计过程说明与判定口径

## 审计范围
- 原版：`原版易语言源代码/源码/*.ecode` 与 `使魔大战.txt`
- 新版：`server/src/modules/**`、`server/prisma/data/**`、指令 seed
- 本目录每个域表均按「门禁 → 执行/消耗 → 输出 → 后续触发」记录；只存在入口不视为迁移完成。

## 状态定义
- ✅：当前代码证据足以确认主行为链闭环，只有措辞或平台承载差异不影响玩法。
- 🟡：入口存在，但公式、门禁、状态、输出、异步链或并发语义存在明确差异。
- ❌：原版有可执行行为，新版当前路径是空壳、错误路由或关键链路缺失。
- 🔧：原版内部延时/回调分支，需通过触发它的玩家指令验证，不将其当成普通玩家指令漏迁。
- ➕：新版平台/产品扩展，原版没有对应玩法；不计入“原版缺失”。

## 本轮复核发现的高优先级问题
详见 `_主进程交叉验证.md`。其中已用原版与新版实际代码交叉读证的重点包括：
1. `传送/跃迁` 当前 game handler 错误调用 `handleMove`，正确 `handleTeleport` 处于未接入死代码状态。
2. `补魔` 当前是喝魔力药剂，与原版「躺下屋内→30 秒延时→兴奋/好感/生崽」完全不同。
3. 手动 `开采` 当前是资源点直接取空，与原版载具采集器三档+60 秒 `开采1c2c` 结算不同。
4. `维修` 当前是维修工具/经验即时修，与原版载具零件+20 秒 `维修wcc1` 不同。
5. `发射信号枪` 与 `召唤货舱` 当前角色反转：新版信号枪引怪，原版信号枪用于 6 秒后召唤货舱。
6. ~~原版管理命令 `刷新怪物`、`生成人物` 在新版仍为占位存根。~~ ✅ 已实装（2026-09-06，见 移动与地图.md 域总览与第8节）。
