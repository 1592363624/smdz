# 特效 / 装备「描述文案 ↔ 实际实现」一致性审计

审计时间：2026-09-22。范围：`server/prisma/data/` 的 effects.json（55 条特效）、equipments.json（360 件装备，含 40 个武器特殊序号、133 个装备特殊序号）、set-effects.json、items.json、buffs.json、titles.json，对照 `server/src/modules/game/` 的战斗、属性、指令实现，并以 `原版易语言源代码/源码/*.ecode` + `使魔大战.txt` 为移植参照。

判定口径：**玩家读到的描述为准**。凡「实现与描述不一致」，按描述改实现；若描述本身与原版设计矛盾（无畏套装、麻醉枪），本轮只登记不改代码，见「需要拍板」。

## 二、审计中确认但本轮未改（需要更大改动或先拍板）

### A0. 最大的一条：整个「防御方装备/被动层」只做在攻击方向

原版 造成伤害() 是一个对攻守双方通用的子程序（z1=攻击方、z2=防御方），所以「格挡、套装类型减伤、免疫、反伤、增强器、铃铛/圆盾/含光/军姬…防御方被动」在玩家被打时同样生效。
本框架把两个方向拆成了 `weaponAttackInner`（玩家打怪）与 `monsterCounterAttackOnePlayer`（怪打玩家），而**防御方被动那一大段只写在前者里**（`blockVal/blockMult/defEquip2/defSets2` 20 处全在 weaponAttackInner）。后果：

- 玩家被怪物攻击时：没有格挡、没有五套类型减伤、没有荆棘之翼/小鱼发饰反伤、没有增强器抗性、没有免疫/招架类被动；而 `defEquip2/defSets2` 取的是**怪物**的装备与套装（怪物没有）→ 同一段代码在 PvE 里对玩家装备一律不生效，只有在竞技场（防御方是玩家）才成立。
- 因此本轮在防御链路（`monsterCounterAttackOnePlayer`）里补了：套装类型减伤（29 件）、格挡判定（含 防爆盾+10/金刚不坏+10/圆盾+5/烟雾弹+20，触发后 ×0.25）、铃铛首次抬档、圆盾三池回满+免疫、反伤（荆棘之翼/小鱼发饰）、增强器（防御方装备传参）、强袭4件受伤害封顶、两件围裙的格挡与易伤、死亡之翼/加速装置的10%必闪、使魔防御被动整段（见第一节）、以及武器伤害配比与元素穿透的结算口径。
- 防御链路上还缺的（按现状复核过，别再按名字出现在攻击方向就判"已实现"）：**幻蝶(32)**「被单体攻击选为目标时把目标转移给别人，冷却30秒」与 **荆棘之翼/含光 的嘲讽**、**含光「使敌人全体攻击变单体」** 同因：本作怪物攻击是 `for (const victim of victims)` 全覆盖，没有单体目标选择模型，属设计级改动（见 B 表）；**隐形披风(26)** 描述两句（采集不激怒 / 进图不被主动攻击）已走 `gather-panel` 的"不排怪物回合"那条豁免，与承伤链路无关；**兰顿之兆(45)/系带(86)** 依赖"怪物对玩家掷暴击"（防御链路 isCrit 现硬编 false，见 B 表下一行），45 的 −10% 被暴击率已在 `calcCritRate` 侧生效、只差没有掷骰。已补齐的防御向装备被动不再列在这里：套装减伤、格挡、围裙、必闪、敏锐/坚毅、永恒主宰、短衬衫、风雷精灵、四糸奈、心形贴、祥瑞、龙之逆鳞、排斥力场、坚韧护盾、圣诞掉礼物、雪獒扣充能、狐狸尾巴自动闪避；攻击侧新补 **直死魔眼(54)** 的斩杀（见第一节末表）。使魔侧与装备侧的入口分别是 `applyDefenderFamiliarPassives` / `applyDefenderGearHitPhase` + `applyDefenderGearDamagePhase` + 扣池阶段那几个方法，新加被动请继续挂进它们，不要再抄一份。

### 顺带发现的结构性死代码

### 载具部件里三处"文案与原版代码口径不同"（已逐条回源码核对，本轮**不改代码**）

1. `生产调度系统` / `生产调度系统II` 都写着「加快5%/9%，这个类型的部件的效果可叠加最多5次」。原版 物品操作.ecode L2728-2763 的实现是**两级共用 5 个生效位**（II 先占，I 只能填 `5 - II` 的余量），不是各自 5 次；本移植与原版一致（`systemI = min(max(0, 5 - systemII), 数量)`）。要按字面文案放开就得改原版算法并动生产平衡 → 留给产品定：要么改文案成"与高级/低级版本共用最多 5 个生效位"，要么改代码。
2. `大型牵引光束`「一次牵引的数量是牵引光束的6倍」。原版 _主程序.ecode L7732-7737 给的是 `b=2, d=24` 对 `b=1, d=6`，而 `d` 是**次数预算**（24/6 = 4 倍），文本的"6倍"对不上任何一个字段；本移植照抄原版（24/6）。这条属原版文案自身的含糊，不是移植缺失。
3. `引力调频器` 说明里自己写着「（未实装，仅与行星解裂器相同效果）」——本移植给了它独立档位 `collector=3`（开采档位链：调频器3 / 解裂器2 / 采集器1），与这句自述一致，无需处理。
