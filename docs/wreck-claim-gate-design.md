# 废弃载具（地面残骸）回收门槛设计

> 状态：设计稿，待评审
> 日期：2026-09-16
> 背景：群内反馈「坠毁的采矿空间站」等无主残骸在生成与获取上零代价，开局号即可开走拆解，
> 一次性获得后期量级的资源（燃料 5 万 / 水晶 2 万 / 钻石 5 万 / 氢弹等），需要设置获取门槛。

## 1. 现状链路（代码定位）

「零代价暴富」的唯一通道是**定时/管理员生成的无主废弃载具**，共四步，全程无任何门槛：

| 环节 | 位置 | 现状 |
| --- | --- | --- |
| ① 定时生成 | `schedule.service.ts` `spawnRandomVehicle()` | 每天 `game.wreckSpawnHour`（默认 10）点必刷 1 个；全图无主残骸数受 `game.wreckMaxCount`（默认 3）约束 |
| ② 管理员生成 | `dungeon-challenge.service.ts` `handleSpawnWreck()` | 管理员指令「废弃载具」，与定时刷新共用 `spawnWreckToRandomMap()`，不受上限约束 |
| ③ 随机落点 | `spawnWreckToRandomMap()`（约 L903-907） | 从 `id≥3` 且非开拓地/关卡/副本/`noSpecial` 的地图中**纯随机**挑一张——新手第一张野外图「森林出口」也在候选池 |
| ④ 产出内容 | `prisma/data/wrecks.json` | 11 种残骸，按 `chance` 倒序掷骰；资源件固定数量，装备件替换为 s 品质成品 |
| ⑤ 认领 | `movement-vehicle.service.ts` `handleDriveVehicle()`（L2393） | 玩家在落点图发「驾驶 XX」，发现 `归属=无主` 后**零校验**直接把归属改为自己（L2520-2523），并触发「拾取载具」成就/任务 |
| ⑥ 取货 | 同文件 `handleAssembleVehicle()`（L2285-2335） | 驾驶/接管后用负数量把零件取进背包；拆掉核心则整车散架，**全部内容物一次性进背包** |

wrecks.json 各档产出（节选暴富点）：

| 残骸 | chance | 代表性产出 |
| --- | --- | --- |
| 废弃的骑士 / 损坏的骑士 | 2% | 骑士核心、基础部件、残骸×100、补给箱 |
| 废弃的兰斯洛特 | 1% | 中型装甲、标准火控、超级计算机 |
| 废弃的采矿车 | 1% | **合金×10000**、资源箱×100 |
| 坠毁的穿梭机 | 1% | **钻石×50000**、破损的小型跃迁引擎 |
| 可疑的移动工厂 | 1% | 标准生产线×2、具现装置 |
| 坠毁的采矿空间站 | 0.8% | **燃料×50000、水晶×20000、能量块×16000**、水晶体×10、能量球×10 |
| 废弃的轻型航母 | 0.6% | 驱逐舰核心、导弹×10 |
| 废弃的采矿船 | 0.4% | **合金×20000**、牵引光束、资源箱×200 |
| 掩埋的幻影骑士 | 0.3% | 超重型反应装甲、电磁炮×2、圣水×20 |

### 其他「地上资源」不需要动

- **货舱 / 能量元素**（每小时整点掉落）：单次产出为概率×1~2 的小料，且必须先拥有载具并安装「牵引光束/大型牵引光束」，带 6 秒冷却与 6/24 次散热预算，天然有门槛；
- **地图资源**（砍树、捡垃圾、地精「载具残骸」等）：有 `times` 次数、`timeScale` 耗时、`renewable` 配置，产出是小概率碎片；
- 真正的异常只有残骸载具的**固定大额产出 + 无门槛认领**。

## 2. 群内三个思路的评估

1. **系统设置里加等级门槛**：方向正确，但只挡「认领」仍不够——大奖残骸仍会刷在新手脸上造成困惑和蹲点；且等级线必须按残骸档位区分，一刀切会连教学级残骸（废弃的骑士）一起挡掉。
2. **认领时按世界等级/玩家等级扣资源**：不建议作为主方案。
   - 资源凭空蒸发，体验上像 bug，必须逐条弹明细；
   - 「扣多少」同样要逐档调参，调参工作量与硬门槛相同，却留下「残血大奖」的困惑；
   - 世界等级由全服击杀熟练度换算（`global-proficiency.service.ts` `worldLevel()`），老服新人会被与个人进度无关的数字卡。
   - 可作为「不接受硬挡」时的软方案保留（见第 5 节）。
3. **资源生成少一点**：只调总量不解决「1 级也能拿」——砍半后 5 万燃料仍是 2.5 万的天降横财。适合作为运营补充旋钮，不是主修。

## 3. 推荐方案：三层门槛（全部配置化，后台即改即生效）

### 第 1 层：残骸分档 + 认领等级门槛（核心硬门槛）

- **数据层**：`wrecks.json` 每条增加可选字段 `requireLevel`（固定配置进 JSON，符合项目「固定配置 22 个 JSON、可调参数进 SystemConfig」的分层约定）。
- **生成盖戳**：`spawnWreckToRandomMap()` 生成时把需求等级写入载具运行时字段（`需求等级` / `requireLevel` 双字段镜像，与现有 `归属/owner` 写法一致），随 `map.vehicles` 持久化。
- **认领校验**：`handleDriveVehicle()` 在归属校验通过后、写入归属前，当目标「无主」且带需求等级戳时：
  - `player.level < requireLevel` → 拒绝驾驶/认领，返回明确提示（当前等级、需求等级、残骸名）；
  - 只拦「**首次认领无主残骸**」这一个口：玩家自制载具没有戳、已归属载具、接管自己的载具均不受影响；
  - `ADMIN` / `SUPER_ADMIN` 角色绕过（方便测试与活动投放）；
  - **存量兜底**：升级前已刷出的老残骸没有戳，按载具名回查 `wrecks.json` 取 `requireLevel`；查不到（玩家自制车）不拦。
- **系统配置（SystemConfig 表，/admin 在线改）**：
  - `game.wreckClaimLevelGate`（boolean，默认 `true`）：总开关；
  - `game.wreckLevelReqOffset`（number，默认 `0`）：全档需求等级统一加减，例如觉得太难就填 -5；
  - `game.wreckGateBasis`（string，默认 `player`）：等级口径，可选
    `player`（玩家个人等级，默认）/ `world`（世界等级×系数，系数另配）/ `max`（两者取高）。
    把群里提到的「世界等级」口径做成可选项，默认仍用个人等级，避免老服新人被误伤。

### 第 2 层：落点保护（大奖不刷新手村）

- 新增配置 `game.wreckProtectedMaps`（json 数组）：保护地图名单，建议初值
  `森林出口、森林深处、雪原、远峰、城镇出口、城镇中心、城镇老区、草原、湖边`（可再议）。
- `spawnWreckToRandomMap()` 掷出残骸后过滤候选图：
  - 高需求档（建议 `requireLevel > 10`）不得落在保护图，掷到则重选候选图（带次数护栏，避免死循环）；
  - 保护图最多只刷教学档残骸。
- 管理员手动「废弃载具」建议**绕过**落点保护（运营有意投放），但需求等级戳照样盖（管理员本人可绕过认领门槛）。

### 第 3 层：产出总旋钮（回应「生成少一点」）

- 新增配置 `game.wreckLootFactor`（number，百分比，默认 `100`）。
- 拼装残骸零件时，仅对**资源类**零件的数量乘该系数（核心与 s 品质装备成品不缩放，避免出现 0.5 个核心/装备）。
- 属于运营阀门，不是主门槛。

## 5. 软门槛备选（若评审不接受硬挡）

「认领不拦、拆取时解封」：

- 允许驾驶残骸，但从车上取资源 / 拆核心时校验等级；
- 不足部分**不删除**，以「加密货舱」状态留在车上，达到等级后才能取出。

缺点：需要在载具零件上额外持久化封存状态，载具查看/取出/散架的文案与逻辑都要改，工作量明显大于硬门槛；
且残骸本就因部件超限无法正常运作（见载具面板「有部件超过了可安装上限，载具无法正常运作」），
「先进去再说」没有实际收益。因此推荐硬门槛，本方案仅作备选。

## 7. 边界与注意

- **接管指令**（`handleTakeoverVehicle`）只允许接管本人名下载具，不涉及无主认领，无需改动；
- **自制载具**：组装流程产出的载具不带需求等级戳，永远不受门槛影响；
- **存量残骸**：上线时全图最多 3 个无主残骸，按名回查档位；查不到不拦，宁可漏拦不可误伤；
- **成就/任务**：「拾取载具」成就与任务推进在成功认领后才触发（L2555-2558），门槛拦截在其之前，不会出现成就拿到了车没拿到；
- **等级口径**：玩家 `player.level` 从 1 起步；世界等级仅在 `game.wreckGateBasis` 显式配置为 `world/max` 时参与；
- **被挡住的残骸仍占 `wreckMaxCount` 上限**：留给达到等级的玩家。若运营发现长期无人能开，可调 `wreckLevelReqOffset` 降低门槛或手动清理；
- **凭证、补给箱等「一件质变」物件**：硬门槛挡住整车认领即可，不需要对单件产出再做概率裁剪；
- **提示文案建议**：
  `{玩家}无法获取{残骸名}的回收权限：需要等级 Lv.{需求}（当前 Lv.{现状}）`，
  与现有「这是别人的XX，你不能驾驶」的口吻保持一致。
