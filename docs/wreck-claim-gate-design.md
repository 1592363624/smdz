# 废弃载具 · 远古遗迹回收门槛设计

> 状态：设计稿 v2，待评审
> 日期：2026-09-16
> 背景：群内反馈「坠毁的采矿空间站」等无主残骸零代价即可获取，开局号直接开走拆解，
> 一次获得后期量级资源（燃料 5 万 / 水晶 2 万 / 钻石 5 万 / 氢弹等）。
> 方向定调（v2）：载具是中后期内容，认领等级门槛整体拉到 **100 级起步**；
> 且把无主残骸设计成「远古大能遗留的载具遗迹」——获得它需要像闯关一样付出代价。

## 1. 现状链路（代码定位）

「零代价暴富」的唯一通道是**定时/管理员生成的无主废弃载具**，共四步，全程无门槛：

| 环节 | 位置 | 现状 |
| --- | --- | --- |
| ① 定时生成 | `schedule.service.ts` `spawnRandomVehicle()` | 每天 `game.wreckSpawnHour`（默认 10）点必刷 1 个；全图无主残骸受 `game.wreckMaxCount`（默认 3）约束 |
| ② 管理员生成 | `dungeon-challenge.service.ts` `handleSpawnWreck()` | 与定时刷新共用 `spawnWreckToRandomMap()`，不受上限约束 |
| ③ 随机落点 | `spawnWreckToRandomMap()`（约 L903-907） | 从 `id≥3` 且非开拓地/关卡/副本/`noSpecial` 地图纯随机——新手图也在池内 |
| ④ 产出内容 | `prisma/data/wrecks.json` | 11 种残骸，按 `chance` 倒序掷骰；资源件固定数量，装备件替换为 s 品质成品 |
| ⑤ 认领 | `movement-vehicle.service.ts` `handleDriveVehicle()`（L2393） | 发「驾驶 XX」发现 `归属=无主` 后零校验直接改归属（L2520-2523） |
| ⑥ 取货 | 同文件 `handleAssembleVehicle()`（L2285-2335） | 驾驶/接管后负数量取零件；拆核心整车散架，全部内容物一次进背包 |

其他「地上资源」不需要动：货舱/能量元素需先有载具+牵引光束+6s 冷却+散热预算；地图资源有次数/耗时；地精「载具残骸」是小概率碎片。真正的异常只有残骸载具的**固定大额产出 + 无门槛认领**。

## 2. 设计定位（v2 定调）

1. **无主残骸 = 远古遗迹**：它是前辈大能留下的载具遗骸，被远古禁制封印。
   - 观察附近可以看到它，但状态显示「远古遗迹 · 被封印」；
   - 直接「驾驶」会被禁制弹开，提示需要先「唤醒遗迹」；
   - 唤醒 = 等级资格 + 献祭贡品 + 击破守卫（像闯关一样）。
2. **等级线整体拉到 100+**：载具是中后期内容；100 级前玩家安心发育，不接触遗迹。
3. 不采用「认领时扣资源」：资源凭空蒸发体验像 bug、调参量与硬门槛相同；
   世界等级口径会误伤老服新人，故默认用**玩家个人等级**，世界等级做成可选项。

## 3. 推荐方案：遗迹化 + 三层门槛（全部配置化）

### 第 1 层：等级资格（硬门槛，100 起步）

- **数据层**：`wrecks.json` 每条增加 `requireLevel`（认领等级）。
- **生成盖戳**：`spawnWreckToRandomMap()` 生成时写入载具运行时字段（`需求等级`/`requireLevel` + `封印等级`/`sealLevel` 双字段镜像，与现有 `归属/owner` 写法一致），随 `map.vehicles` 持久化。
- **认领校验**：`handleDriveVehicle()` 在归属校验通过后、写入归属前，无主残骸带封印时：
  - `player.level < requireLevel` → 拒绝并提示差距；
  - 只拦「首次认领无主残骸」这一个口：自制车无戳、已归属车、接管自己的车均不受影响；
  - `ADMIN` / `SUPER_ADMIN` 绕过（方便测试与活动投放）；
  - **存量兜底**：升级前已刷出的老残骸无戳，按载具名回查 `wrecks.json` 取 `requireLevel`；查不到不拦。
- **系统配置**：
  - `game.wreckClaimLevelGate`（boolean，默认 `true`）总开关；
  - `game.wreckLevelReqOffset`（number，默认 `0`）全档等级统一加减（觉得太难填负值）；
  - `game.wreckGateBasis`（string，默认 `player`）等级口径：`player` / `world`（世界等级×系数）/ `max`（取高）。

### 第 2 层：唤醒遗迹 = 献祭 + 守卫战（闯关玩法，核心差异）

无主残骸带封印时，认领前必须先完成「唤醒」流程，新指令 **「唤醒 载具名」**：

**流程：资格 → 献祭 → 守卫战（N 波）→ 解除封印 → 正常驾驶认领**

1. **资格检查**：`player.level ≥ requireLevel`（同一档位）。
2. **献祭贡品**（付出资源，从背包扣除，按档位配置在 wrecks.json 的 `sealCost`）：
   - 示例（档位越高越多）：燃料、能量块、合金、水晶、凭证 等组合；
   - 缺省值按 `requireLevel` 自动推导（见第 4 节），管理员可逐条覆盖。
3. **守卫战**（复用现有战斗链路，工程量可控）：
   - 在残骸所在地图的 `tempMonsters` 生成守卫怪（参照 `handleNextChallengeLevel` 的挑战怪机制），玩家用现有攻击/战斗指令作战；
   - 波数 `guardWaves`（按档位 1~3 波），每波守卫等级 ≈ `requireLevel`，怪物模板统一用「遗迹守卫」族（可在 monsters.json 新增 1 个模板 + 按等级成长）；
   - 每波守卫战消耗活力（复用 `vitality.service.ts`），失败后守卫原地保留，玩家需恢复活力再战；
   - **全波击破 → 封印解除**：清除载具的封印字段，改为正常无主载具（可被任何达到等级的人驾驶），玩家本人直接获得归属 + 成就「遗迹征服者」。
4. **失败/离开**：守卫战失败或中途离开不摧毁残骸，也不退还已献祭的贡品（闯关的代价感）；若长期无人解封，残骸继续占 `wreckMaxCount` 上限。
5. **可扩展**：后续可加「组队唤醒」（允许多人一起打守卫）、「限时守卫」（一段时间未打完守卫增强），本期不做。

### 第 3 层：落点保护 + 产出阀门

- **落点保护**：新增 `game.wreckProtectedMaps`（json 数组，默认新手早期图 9 张）；
  `requireLevel > 10` 的遗迹不落在保护图，掷到则重选（带护栏）。
  ——等级线到 100 后保护图实际只剩「教学档」问题，保留用于低档遗迹不上新手脸。
- **产出阀门**：新增 `game.wreckLootFactor`（number 百分比，默认 100）；
  拼装残骸零件时仅对**资源类**零件数量乘系数，核心与 s 品质装备成品不缩放。

## 7. 边界与注意

- **接管指令**（`handleTakeoverVehicle`）只允许接管本人名下载具，不涉及无主认领，无需改动；
- **自制载具**：组装流程产出的载具不带封印戳，永远不受影响；
- **存量残骸**：上线时全图最多 3 个无主残骸，按名回查档位并补封印；查不到不拦，宁可漏拦不可误伤；
- **成就/任务**：「拾取载具」成就与任务在成功认领后触发（L2555-2558），守卫战在其之前，不冲突；
- **守卫战并发**：同一残骸的守卫战建议加标记锁（玩家 marker 或地图 tempMonsters 唯一性），避免多人同时唤醒同一遗迹互相覆盖；
- **守卫怪与玩家强度**：守卫等级按 `requireLevel` 生成，默认略高于同等级普通怪（遗迹该有难度）；打不过可升级/换装后再来，守卫原地保留不重置；
- **活力**：守卫战消耗活力，与普通击杀同源，失败同样扣（代价的一部分）；
- **被挡住的残骸仍占 `wreckMaxCount` 上限**：留给达标玩家。若长期无人能开，调 `wreckLevelReqOffset` 或 `wreckSealCostFactor`（献祭系数）降低门槛。

## 8. 分阶段落地建议

- **Phase 1（先止血）**：等级门槛 + 封印状态 + 查看面板提示。无守卫战，唤醒=等级+献祭。
  工作量最小，立刻堵住零代价暴富。
- **Phase 2（闯关体验）**：守卫战 + 波次 + 成就「遗迹征服者」+ 活力消耗。
  在 Phase 1 之上增量实现，体验闭环。
- 两阶段共用同一份数据字段与配置键，先上 Phase 1 不会造成返工。
