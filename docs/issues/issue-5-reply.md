## 回复正文

感谢反馈，三个问题我们都排查完了，结论如下：

### 1. 切换武器「提示切换成功但手上武器不变」 ✅ 已修复

**原因**：旧版本的武器索引口径存在错位（`currentWeapon` 1-based 与 `weapons[]` 0-based 混用），按武器名切换时目标索引整体偏移一位，导致提示已切换但实际手中武器未变。这与你的复现完全吻合（先装提卡、再装纵横，`切换武器纵横` 无效）。

**状态**：已在本轮重构中修复（统一 1-based 口径、对齐原版 `_主程序.ecode L4303-4432` 的交互），并补充了 18 个切换武器回归测试用例。将随下个服务端版本发布，届时更新后即可生效。

### 2. 「锁定传说 / 锁定神迹 / 分解全部」失效 ⏳ 功能缺失，开发中

**原因**：经与原版对照（`_主程序.ecode L3527-3620` / `L3387-3435`），复刻版目前只实现了**单件**的 `锁定装备1` / `锁定装备名字`，尚未实现原版的：

- `锁定装备传说` / `锁定装备神迹` / `锁定装备史诗` / `锁定装备精良` / `锁定装备优秀`（按品质批量锁定）
- `分解全部`（一键分解背包内全部未锁定装备，自动跳过植入体/增幅器，含彩虹鸟加成结算）

所以不是老流程坏了，而是这两个指令还没复刻出来。

**状态**：已列入开发计划，将严格按原版行为补齐。补齐后「开箱 → 锁定传说 → 锁定神迹 → 分解全部」的原有流水线即可恢复。

### 3. 任务「教程-战斗准备」无法完成 🐛 确认为判定 Bug

**原因**：该任务要求「使用装备 ×1 + 使用武器 ×1」。服务端的武器判定函数与原版规则不一致——原版规则为：

- 特殊序号 ≠ 0 时：负数才是武器（如提卡 = -7 ✅）
- 特殊序号 = 0 时：类型以「武器」结尾或为「工具」才算武器

而复刻版错误地把「特殊序号在 1~99 之间」也判为武器，导致**皇冠（特殊序号 28）等 149 件特殊装备全部被误判成武器**。于是你装备皇冠时，任务推进的是「使用武器」而不是「使用装备」——「使用装备」进度永远是 0，任务自然永远完不成。你反复卸下/重穿是不会有效的，问题不在操作。

**状态**：修复方案已确定（按原版规则重写判定函数），修复后该任务会正常推进，已获得的装备进度无需重置。
